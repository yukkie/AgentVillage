# AgentVillage 仕様書

## 概要

LLMエージェント同士が自律的に人狼ゲームをプレイする社会シミュレーションゲーム。
プレイヤーはAIたちの会話・推理・裏切りを観察し、間接的に介入する観戦型ゲーム。

アーキテクチャ・技術選定・ADR は [Architecture.md](Architecture.md) を参照。
アイデア・未決事項は [Ideas.md](Ideas.md) を参照。

---

## 1. 目的（Goal）

- LLMエージェントが人狼ゲームのルールに従って自律的にプレイする
- プレイヤーは観戦者として社会を観察・間接介入できる
- エージェントの人格を育成・カスタマイズする体験を提供する

## 2. ゲームルール

### 2.1 基本構成

| 項目 | 内容 |
|---|---|
| プレイヤー数 | 5 / 7 / 9エージェント（`config/roles.json` で編成設定） |
| 役職（村人陣営） | 村人 / 占い師 / 霊媒師 / 騎士 |
| 役職（人狼陣営） | 人狼 / 狂人 |
| 勝利条件（村人側） | 人狼を全員追放 |
| 勝利条件（人狼側） | 人狼数 ≥ 村人数（狂人は村人側としてカウント） |

#### 役職一覧

| 役職 | 陣営 | 夜行動 | 能力 |
|---|---|---|---|
| 村人（Villager） | 村人 | なし | なし |
| 占い師（Seer） | 村人 | inspect | 対象の真の陣営（狼 / 非狼）を知る |
| 霊媒師（Medium） | 村人 | なし（受動） | 昼の処刑直後、処刑者の真の役職を知る |
| 騎士（Knight） | 村人 | guard | 対象を狼の夜襲から守る |
| 人狼（Werewolf） | 人狼 | attack | 毎夜、村人陣営1名を襲撃する |
| 狂人（Madman） | 人狼 | なし | 人狼を知らず、人狼からも正体は知られない。人狼が勝てば勝利 |

#### 標準編成

| 人数 | 村人 | 占い師 | 霊媒師 | 騎士 | 人狼 | 狂人 |
|---|---|---|---|---|---|---|
| 5人 | 3 | 1 | — | — | 1 | — |
| 7人 | 3 | 1 | — | 1 | 2 | — |
| 9人（中級） | 3 | 1 | 1 | 1 | 2 | 1 |

### 2.2 ターン構成

```
[昼フェーズ]
  1. 判断→発言ターン × 最大2回（DISCUSSION × 2）
       a. 全エージェントが並列で「判断」する（最大4択）
            - "challenge": 特定の発言（speech_id指定）に突っ込む
            - "speak":     追加で発言する
            - "silent":    発言せずに見守る
            - "co":        役職を公言（COする）— 適格エージェントのみ選択可
              適格条件: claimed_role is None かつ role != "Villager"
              （未COの非村人役職。占い師・霊媒師・騎士・人狼・狂人が対象）
       b. "challenge" / "speak" / "co" のいずれかを選んだエージェントだけ発言を生成する
          challenge の場合、どの speech_id への反応かを発言に含める
          co の場合、発言生成プロンプトに役職公言の指示が追加され、発言後に
          claimed_role が更新される
  2. 投票（VOTE）
       各エージェントに投票専用の LLM 呼び出し（call_vote）を行う
       投票プロンプトには議論ログ全体・past_votes・past_deaths・発言フェーズ
       で蓄積された最終 vote_candidates・狼の場合は仲間情報＋VOTE STRATEGY を含む
       LLM が返す VoteOutput.target を投票先として採用
       システムが多数決を集計 → 最多得票者を追放
  3. 霊媒結果の解決
       霊媒師が生存している場合、処刑直後に処刑者の真の役職を霊媒師へ通知する
       この情報は非公開で、観戦者ログにのみ記録される
  4. 勝利判定

[夜フェーズ]
  1. 宣言フェーズ
       人狼が襲撃対象を選択（複数狼の場合は狼チャットで合意）
       狼チャットでは翌昼の偽CO方針も協議できる
       - 各狼は「自分が次の昼に何を名乗るか / まだ待つか」を非公開で決められる
       - 両狼がCOする・片方だけCOする・両方待つ・同じ役職を名乗る、のいずれも許容される
       騎士が護衛対象を選択
       占い師が占い対象を選択
  2. 解決フェーズ
       占いを優先して実行し、副作用を即時反映する
       その後、護衛と襲撃を解決する
  3. 公表フェーズ
       占い師が生存している場合のみ、占い結果を本人のbeliefに反映し観戦者ログへ記録する
       護衛成功や夜死亡の通知を行う
  4. 勝利判定

→ 決着がつくまで昼夜を繰り返す
```

### 2.3 情報の公開範囲

| 種類 | 例 | 公開先 |
|---|---|---|
| Public | CO・投票・死亡・発言 | 全エージェント |
| Private | 本当の役職・夜の結果 | システムのみ（LLMには渡さない） |
| Wolf-only | 狼仲間の名前 | 人狼エージェントのみ（昼フェーズのプロンプトに明示）。仲間が全滅した場合は「あなたが最後の人狼」と伝える |
| Personal | 疑い・信頼・推理 | 本人のみ |

## 3. エージェント仕様

### 3.1 エージェントの構成要素

- 役職（システム管理）
- 性格プロンプト（コミュニティカスタマイズ可）
- 役職プロンプト（役職ごとの行動指針）
- 記憶（short-term: 当日の発言ログ）
- 信念モデル（他エージェントへの疑い・信頼スコア）

### 3.2 思考と発言の分離

各エージェントは**思考**（腹の中）と**発言**（表の言葉）を別々に持つ。
思考の一部を発言に滲ませる「灰ログ」的演出を行う。

### 3.3 LLM出力フォーマット

LLMの出力は必ずJSONで受け取る。フェーズによって複数のフォーマットを使い分ける。

#### (A) 発言フォーマット（DISCUSSIONの発言生成・tool use）

DISCUSSION では Claude の tool use を使い、判断と発言を1回の API コールで生成する。
LLM は `speak` / `challenge` / `co` / `silent` の4 tool から1つを選び、そのパラメータに発言内容を格納する。

**speak / challenge tool（発言・反論）**

```json
{
  "thought": "SQは昨日の票替えが不自然。おそらく人狼。",
  "speech": "今日はSQを疑っています。昨日の票替えが不自然でした。",
  "memory_update": ["SQの票替えを黒要素として維持"],
  "suspicion_scores": {"SQ": 0.74, "Raqio": 0.42},
  "threat_scores": null
}
```

challenge の場合は追加で `reply_to: int`（反論対象の speech_id）を含む。

**co tool（役職公言）**

```json
{
  "thought": "今日CO宣言すべきタイミング。",
  "speech": "私は占い師です。昨夜SQを占い、人狼と出ました。",
  "claim_role": "Seer",
  "memory_update": [],
  "suspicion_scores": {"SQ": 0.9}
}
```

**silent tool（沈黙）**

```json
{
  "reasoning": "まだ情報が少ないので様子を見る。"
}
```

#### (B) 投票フォーマット（VOTE フェーズ専用）

```json
{
  "target": "SQ",
  "reasoning": "DISCUSSION での占い結果と票の不自然さから SQ が最も人狼濃厚と判断した。",
  "strategy": "wolf_side"
}
```

| フィールド | 型 | 内容 |
|---|---|---|
| `target` | `str` | 投票先（生存者、自分自身を除く） |
| `reasoning` | `str` | 投票理由（観戦者向け）。VOTE LogEvent の `reasoning` に格納 |
| `strategy` | `"village_side" \| "wolf_side" \| null` | **狼のみ**設定。`village_side` は村人として自然な投票（仲間への投票も許容、ライン切り戦略を含む）／ `wolf_side` は狼として有利な投票先。村人陣営は常に `null` |

#### (D) 判断フォーマット（DISCUSSIONの判断フェーズ・軽量）

```json
{
  "decision": "challenge",
  "reply_to": 3,
  "claim_role": null,
  "reasoning": "Alice's claim contradicts yesterday's vote pattern."
}
```

| フィールド | 型 | 内容 |
|---|---|---|
| `decision` | `"challenge"` \| `"speak"` \| `"silent"` \| `"co"` | 行動の選択。`"co"` は適格エージェント（未COの非村人役職）のみ有効 |
| `reply_to` | `int` \| `null` | `challenge` 時に突っ込む発言のspeech_id。他は null |
| `claim_role` | `str` \| `null` | `decision="co"` のときに公言する役職。他は null。未指定時は役職ごとのデフォルトにフォールバック |
| `reasoning` | `str` | なぜこの行動を選んだかの短文（観戦者向け）。省略時は `""` |

判断プロンプトには、適格エージェントに対してのみ `"co"` の選択肢と役職別の戦略ヒント（例: 占い師の単独CO、人狼の偽CO、狂人の勝利確定COなど）を含める。不適格なエージェントが万一 `"co"` を返した場合、エンジン側で `"speak"` にフォールバックする。

### 3.4 行動（構造化アクション）

LLMが行動を提案し、システムが検証・実行する。

| Action | 内容 |
|---|---|
| `vote(target)` | 投票 |
| `co(role)` | カミングアウト |
| `accuse(target)` | 非難 |
| `defend(target)` | 擁護 |
| `ask(target)` | 質問 |
| `guard(target)` | 護衛（騎士用） |
| `inspect(target)` | 占い（占い師用） |
| `attack(target)` | 襲撃（人狼用） |

## 4. 人格システム

### 4.1 人格パラメータ

| パラメータ | 意味 |
|---|---|
| Logic | 論理性 |
| Emotion | 感情表現 |
| Aggression | 攻撃性 |
| Cooperation | 協調性 |
| Suspicion | 疑い深さ |
| Charisma | 説得力 |
| Honesty | 正直さ |
| Deception | 嘘能力 |
| Memory | 記憶重視度 |
| Intuition | 直感 |

人格パラメータはプロンプトに変換してLLMに渡す。

### 4.2 キャラクター属性（Persona）

`Persona` はキャラクターの個性を定義するフィールド群。ゲームをまたいで固定。

| フィールド | 型 | 意味 | 例 |
|---|---|---|---|
| `style` | `str` | 性格の文字列説明 | `"logical, calm, empathic"` |
| `lie_tendency` | `float` | 嘘のつきやすさ（0.0〜1.0） | `0.1` |
| `aggression` | `float` | 攻撃性（0.0〜1.0） | `0.2` |
| `gender` | `str \| None` | 性別 | `"male"` / `"female"` / `"non-binary"` / `null` |
| `age` | `str \| None` | 年齢または年代 | `"17"` / `"teen"` / `"adult"` / `null` |
| `speech_style` | `str` | 口調 | `"polite"` / `"casual"` / `"blunt"` / `"gentle"` / `"tsundere"` |

`speech_style` は特に日本語モードで効果が大きい（敬語・タメ口・ぶっきらぼう・ツンデレ等）。

### 4.3 プロンプト構成

各エージェントへのプロンプトは2つに分離する：

1. **性格プロンプト** — Personaフィールドから生成。コミュニティがカスタマイズ可能
2. **役職プロンプト** — 役職ごとの行動指針（村人・人狼・占い師）

## 5. 表示仕様（CLI）

Rich を使用したカラー表示。

色の方針：**村人陣営は青・緑系、人狼陣営は赤・橙系**で統一する。

| 役職 / ログ種別 | スタイル | 備考 |
|---|---|---|
| 村人の発言 | 白（デフォルト） | |
| 占い師の発言 | 青 | 真の役職 or claimed_role が "Seer" のとき |
| 霊媒師の発言 | シアン | 真の役職 or claimed_role が "Medium" のとき |
| 騎士の発言 | 明るい緑 | 真の役職 or claimed_role が "Knight" のとき |
| 人狼の発言（表） | 白（デフォルト） | public モードでは役職不明のため |
| 人狼の発言（観戦者） | 赤 | spectator モードで真の役職が "Werewolf" |
| 狂人の発言（観戦者） | オレンジ | spectator モードで真の役職が "Madman" |
| 人狼の襲撃ログ（観戦者のみ） | 赤 | |
| 占い結果ログ（観戦者のみ） | シアン | |
| 霊媒師結果ログ（観戦者のみ） | 黄（太字） | MEDIUM_RESULT イベント専用 |
| 護衛ログ（観戦者のみ） | 明るい緑 | 騎士役職色と統一 |
| 護衛成功ログ（観戦者のみ） | 明るい緑・太字 | 騎士役職色と統一 |
| 投票候補ログ（観戦者のみ） | dim cyan | VOTE_CANDIDATES イベント。発言フェーズ中の vote_candidates 変化を可視化 |
| 死亡通知 | 赤・太字 | |
| フェーズ区切り | 黄・太字 | |
| reasoning テキスト（観戦者ログ） | dim（薄色） | VOTE / GUARD / INSPECTION / JUDGMENT の補足情報。主要情報と同一スパンに混在させない |

**public モードと spectator モードの色の扱い**
- public モード: `claimed_role` が設定されている場合のみ役職色を適用。未COのエージェントは白
- spectator モード: 真の `role` で常に色付け

観戦者視点（真実ログ）と公開ログを色で視覚的に区別する。

## 6. リプレイモード

### 6.1 起動オプション

```bash
uv run main.py --replay               # public モードでリプレイ
uv run main.py --replay --spectator   # spectator モードでリプレイ
```

`--replay` フラグを指定するとリプレイモードで起動し、ゲームは実行されない（LLM 呼び出し一切なし）。

### 6.2 アーカイブ選択UI

- `state_archive/` 内のフォルダを新しい順にリスト表示する
- フォルダが 0 件の場合は "No archives found." を表示して終了
- 上下キーでカーソル移動、ENTER で選択、Q / ESC でキャンセル

```
Select an archive to replay:

  > 20260405_170024
    20260403_092211
    20260401_154033

[↑↓] Move  [Enter] Select  [q] Quit
```

### 6.3 ページャー操作

選択後、ログを画面に流す。画面が埋まったら自動停止し、以下のキー入力を受け付ける。

| キー | 動作 |
|---|---|
| SPACE / f / ENTER | 1 ページ進む |
| b / BACKSPACE | 1 ページ戻る |
| j / ↓ | 1 行進む |
| k / ↑ | 1 行戻る |
| g | 先頭へ |
| G | 末尾へ |
| q / ESC | 終了 |

画面下部にステータスバーを常時表示する:
```
[Space/f] Page↓  [b] Page↑  [j/↓] Line↓  [k/↑] Line↑  [q] Quit  (Line 1-30 / 120)
```

全行を表示し終えると "End of replay." を表示して終了。

### 6.4 spectator / public モードの切り替え

既存の観戦モードと同一の切り替えロジックを使用する。
- **public モード**: `is_public=True` のイベントのみ表示（非COエージェントは白）
- **spectator モード**: 全イベントを表示（真の役職で色付け）

## 7. 勝敗以外の評価指標

| 指標 | 内容 |
|---|---|
| 生存率 | 生き残る能力 |

## 8. 懸念事項・留意点

- 投票が同数の場合の処理（ランダム選択 or 再投票）を決める必要がある
- LLMが役職に反する行動（村人がCO拒否など）を提案した場合のフォールバック
- 思考ログのデバッグ表示と観戦表示の切り替えUI（未決）
